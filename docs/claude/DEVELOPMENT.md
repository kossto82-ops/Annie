# Jarvis — Development Workflow

## Primary goal

Make changes with the smallest possible context and smallest coherent diff.

## Before changing code

1. Read `docs/claude/AI_CONTEXT.md` only if project orientation is needed.
2. Identify the target module. To *locate* it cheaply — "what depends on X?",
   "where is Y used?", "what connects A to B?" — query the **graphify** MCP tools
   (`get_node`, `shortest_path`, `god_nodes`, `query_graph`) first; they return
   `file:line` pointers, not file dumps. See `docs/graphify.md`. If the graph is
   stale, `graphify update .` (deterministic, ~8 s). Skip Graphify for a symbol
   whose location you already know.
3. Search for its direct callers/tests with `rg` (or `get_neighbors`).
4. Read the target file and closest tests.
5. Only expand into adjacent modules when the dependency requires it.

## Do not do this by default

- Do not read `STATUS.md` from top to bottom.
- Do not read every source file.
- Do not read every test.
- Do not inspect `.git`, caches, generated bytecode, or virtual environments.
- Do not perform a broad architectural refactor for a local feature.
- Do not rewrite documentation after every tiny implementation change.

## Efficient investigation commands

Prefer commands such as:

```bash
rg "symbol_name|class_name|method_name" src tests
sed -n '1,220p' path/to/file.py
pytest tests/path/to/test_file.py -q
ruff check src/path/to/file.py tests/path/to/test_file.py
pyright
```

Use the repository tree only to locate relevant files.

## Testing strategy

Use a narrow-to-broad sequence:

1. Targeted test(s).
2. Related test module(s).
3. Full suite when the change is cross-cutting or before declaring a milestone complete.

Do not run live provider tests unless the task explicitly concerns live integration.

## Editing strategy

- Preserve existing public APIs unless the task requires a change.
- Prefer the smallest change that preserves invariants.
- Add tests for new behaviour and regression cases.
- Do not rename unrelated symbols.
- Do not reformat unrelated files.
- Do not add dependencies without a concrete need.

## When a task is ambiguous

Ask one concise clarification if choosing between materially different architectures. Otherwise choose the option that best preserves the existing domain boundaries and explain the assumption.

## Documentation strategy

Use:

- `JARVIS_VISION.md` for foundational philosophy/specification.
- `STATUS.md` for chronological history.
- `docs/claude/` for stable AI working context.
- `README.md` for human-facing project overview.

Do not duplicate the entire status log into AI context documents.

## Token-saving response format

After implementation, prefer:

```text
Changed:
- path/file.py — one-line summary

Tests:
- pytest ...
- ruff ...

Notes:
- one important caveat, if any
```

Do not paste entire files unless explicitly requested.
