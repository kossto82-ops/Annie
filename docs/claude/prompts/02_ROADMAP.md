# JARVIS — ROADMAP DE DESARROLLO

Utilizando exclusivamente el estado real del proyecto auditado, diseña el roadmap de desarrollo de Jarvis.

NO implementes código todavía.

## Objetivo

Evolucionar Jarvis hacia:
> A durable long-term cognitive companion capable of memory, reasoning, reflection, tool use and progressively autonomous action.

No añadas funcionalidades simplemente porque sean técnicamente interesantes.

## Principios

Prioriza:
1. arquitectura correcta
2. capacidades fundamentales
3. coherencia entre módulos
4. testabilidad
5. observabilidad
6. seguridad
7. evolución futura

No optimices prematuramente.
No introduzcas frameworks innecesarios.
No añadas dependencias si no son necesarias.

## Orden

Determina qué debe construirse primero teniendo en cuenta dependencias.

No asumas un orden predeterminado: deriva el orden del código real.

## Para cada capacidad

Define:
- Capability
- Why
- Current state
- Dependencies
- Design
- Files
- Tests
- Risks
- Definition of Done

## Roadmap

Produce fases independientes y comprobables:
`PHASE 0 — Foundation`, `PHASE 1`, etc.

No diseñes una arquitectura ideal desde cero. Evoluciona la existente siempre que sea razonable.

Si una parte debe reemplazarse, explica problema, alternativa, coste, riesgo y beneficio.

NO IMPLEMENTES TODAVÍA.
